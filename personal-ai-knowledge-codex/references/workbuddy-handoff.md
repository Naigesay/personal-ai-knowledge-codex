# Codex 本地整理 → WorkBuddy 写入 IMA

## 分工与状态

Codex：读取已有说明/索引，完成任务，整理本地知识底稿，生成授权范围内的脱敏发布稿。

WorkBuddy：使用它实际可用的 IMA 连接器，核对目标知识空间及现有页，执行更新并回传结果。

只有 WorkBuddy 返回可靠写入证据且内容经核验后才标记已同步。目录、skill 或 ZIP 存在不等于已建立连接。

没有消息或调度能力时，交给用户一段可复制的 WorkBuddy 提示词和本地清单；明确这是人工发起的文件交接，不承诺后台自动执行。不得借用 WorkBuddy 的私有 token、会话数据库或配置凭据。

## 交接文件

在用户已选本地知识库的 `.personal-ai-knowledge/publish/<batch-id>/` 下准备：

- `manifest.json`：批次及目标、条目清单和状态；空队列不捏造待发布内容。
- `pages/`：只放最终待发布脱敏稿，不混入本地完整版、候选或日志。
- `receipt.json`：由执行方生成，Codex 不预填成功。

manifest 至少保存：schema_version、batch_id、status、目标 IMA 知识库的名称及可获得 ID（未知留空，不猜）、每项本地相对路径、标题、内容 SHA-256、操作（create/update）、已知远端资源 ID、授权依据和脱敏范围。

状态：prepared → awaiting_workbuddy → synced；异常使用 blocked 或 conflict。部分成功逐项记录，不能整批提前标 synced。

## WorkBuddy 执行要求

1. 只读指定批次、现有说明/索引及目标页面；目标空间未知时先确认，不能按相似名字随意选库。
2. 只处理清单中明确授权的页面；不扫描上传周边文件，不上传课程原文和阅读笔记，除非用户另外明确要求。
3. 检查发布稿摘要和脱敏范围。发现敏感残留、权限不足或附件丢失就停止该条并报告，不擅自降低保护。
4. 更新已有同一资源；没有 ID 时按精确标题及内容识别，歧义时停下，不重复创建。读取远端修改时间/正文发现并发变化时标冲突，不能静默覆盖。
5. 写入后回读正文，核验预期内容与图片附件；再同步索引。无法回读时记录“写入返回成功、待核验”，不算 synced。
6. 生成 receipt：批次、逐项状态、远端 ID、平台提供的链接（无则不造）、实际核验时间、来源内容摘要及失败原因。日志和回执仅本地保留。

## 交给 WorkBuddy 的提示词范式

“请执行本地批次【绝对路径】中的 manifest.json。先读取我现有 IMA 工作区说明和索引，只向清单指定的知识库写入 pages 中经过确认的脱敏稿。沿用已有同一页面；目标不明、并发修改或敏感残留时停止该项并说明。每项写后回读核验，再生成本地 receipt.json。不要上传课程、源资料、候选及日志，不创建定时任务或改变共享权限。”

替换成真实路径后再交付，不把占位符当作已经可执行的批次。未确定根目录和目标前可以先提供流程，不创建假的空壳知识库或发布任务。

## 后续自动化

先让一条真正需要更新的知识完成上述往返，验证连接、更新同一页与回读能力。用户之后明确要求自动运行时，再接其已用的 WorkBuddy 调度；只使用一个云端写入方。NAS 路径和备份未验证前保持“待配置”，不声称已备份。
