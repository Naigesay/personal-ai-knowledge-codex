# 本地知识底稿与增量

## 结构与范围

优先保留已有布局。确需新建且得到初始化授权时，可采用：

```text
知识库根目录/
  原始资料/
  AI工作区/
    00-说明.md
    00-索引.md
    知识-主题.md
  .personal-ai-knowledge/
    state.json
    processed.jsonl
    log.jsonl
    history/
    publish/
```

知识页标题可用“知识｜主题”，Windows 文件名避免使用 `|` 等不合法字符。HTML 是展示产物；事实、规则与修改以 Markdown 底稿为准。不要覆盖或丢弃原始 HTML、图片及相对链接资源。

资料先保留完整来源，再正式提炼；若用户未授权长期保存，仅完成当前分析，不擅自归档。记录来源标题、路径或平台资源标识、日期、作者/说话人和归属。机器转写标为初稿，不冒充原话核验结果。

## 每次更新

读取旧版 → 明确本次确认范围 → 合并已确认内容 → 记录简短实践依据与适用边界 → 标记替代内容 → 保存 → 更新索引 → 回读检查。

修改前保留上一版于本地历史区，或使用已有版本控制；不要求用户另建 Git。写入失败保留原文件，避免先删除再重建。多人或多设备有未合并修改时先报告冲突，不静默覆盖。

本地 state 记录根目录、工作目标、候选及云端发布目标；processed 记录来源标识、修改时间或内容摘要、处理状态及输出页；log 只追加时间、动作和结果。不要把密码、密钥或不必要的敏感正文写入日志。

只检查授权来源范围内新增或变化的资料。排除 AI工作区、历史、发布稿、状态目录和 AI 生成输出，防止重复吃回。只有正文处理和核对成功后才标记已处理；失败可重试，不跳过未完成来源。

## NAS

默认电脑本地工作、NAS 保存备份与历史版本。没有明确的 NAS 地址、访问能力和目标路径时，不假定已经挂载或备份。

备份先复制到新目标，再检查文件数量和关键文件内容摘要；不默认镜像删除，不传播删除，不改共享权限。NAS 上的完整敏感资料不能直接成为云端上传源。用户明确要求将 NAS 作为工作目录时，尊重其选择并处理连接失败与并发修改。

## 维护

任务反馈驱动迭代；定期维护仅在用户要求或任务需要时进行。提出重复、冲突、过时条目的具体处理建议；不把未使用自动等同失效。清理优先标记与归档，保留来源和替代关系。
